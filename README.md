# netsvc-why-system

강남대학교 네트워크서비스 **3·4주차** 실습 시스템.

이 저장소에서 하는 일은 하나다.

> **내가 만들려는 것을, 왜 만드는지 설명할 수 있게 만든다.**

코드는 쓰지 않는다. 화면도 기능도 정하지 않는다. 그건 5주차부터다.

---

## 시작하기

1. ZIP을 풀고 폴더를 연다
2. 터미널에서 그 폴더로 들어가 Claude Code를 실행한다
3. 첫 커밋을 만들고 GitHub에 올린다 (2주차에 한 것과 같은 방식)

```sh
git init
git add .
git commit -m "왜 시스템 시작"
```

4. 대화창에 이렇게 친다:

```
/why
```

---

## 무엇을 만드는가

`내제품/왜.md` **한 장**을 채운다. 여덟 칸짜리다.

| 칸 | 묻는 것 |
|---|---|
| 1 | 누구를 위한 것인가 |
| 2 | 그 사람의 어떤 문제인가 |
| 3 | 지금은 어떻게 버티는가 |
| 4 | 왜 풀 만한 문제인가 |
| 5 | 무엇이 달라지는가 |
| 6 | 내가 아직 모르는 것 |
| 7 | 왜 지금, 왜 내가 |
| 8 | 생각이 바뀐 지점 |

**새 문서를 만들지 않는다.** 이 한 장을 3주차에 v1으로 채우고, 4주차에 v2로 고친다.
학기 내내 이 문서 위에 쌓아 올린다.

## 스킬 네 개

| 언제 | 스킬 | 하는 일 |
|---|---|---|
| 3주차 | `/why` | 칸을 하나씩 채운다 |
| 3주차 | `/assume` | 내가 뭘 모르는지 찾아내고, 가장 위험한 가정 하나를 고른다 |
| 4주차 | `/ask` | 그 가정을 확인할 문장·방법·질문을 준비한다 |
| 4주차 | `/evidence` | 듣고 온 것을 정리하고, 판단을 고친다 |

## 폴더

```
내제품/왜.md      ← 여덟 칸. 이 수업의 산출물
내제품/근거.md    ← 4주차. 실제로 들은 말
내제품/기록.md    ← 생각이 바뀐 지점
예시/             ← 좋은 예와 나쁜 예. 읽기만 한다
```

## 이 시스템이 하지 않는 것

**AI가 대신 써주지 않는다.** 물어보면 되묻고, 고르라고 한다.
답답할 수 있다. 그런데 **대신 써준 문장은 4주차에 밖에 나가서 지킬 수 없다.**
사람 앞에서 설명해야 하는 건 AI가 아니라 나다.

**기능 이야기를 받아주지 않는다.** 화면·기능·기술을 말하면 "그건 해결책입니다"라며 돌아온다.
떠오른 아이디어는 `왜.md` 맨 아래 **"나중에 볼 것"** 에 적어 둔다. 지우지 않는다. 5주차부터 쓴다.

**3주차에 `확인함`이 붙지 않는다.** 아무리 확실해도 붙지 않는다.
확인은 4주차에 사람을 만나고 나서 하는 일이다.

## 막혔을 때

- **뭘 만들지 아직 없다** → 최근 일주일에 짜증났던 일 세 개를 적고 `/why`를 시작한다
- **칸을 못 채우겠다** → `[빈칸 — 4주차에 확인]`을 남기고 다음 칸으로 간다. **빈칸은 실패가 아니다.** 4주차에 물어볼 것을 정해 준다
- **AI가 자꾸 되묻는다** → 규칙대로 도는 중이다. 짧게라도 답을 적으면 다음으로 간다
- **설치가 안 된다** → 2주차 `결석학생_빠른시작` 자료를 먼저 본다
