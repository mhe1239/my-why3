# 확인할 준비 — 나가기 전에 끝내야 하는 것

이 스킬이 끝나면 사용자는 **밖에 나가 사람을 만난다.**
준비가 덜 된 채로 내보내면 잘못된 방식으로 물어보고 돌아온다. 그 데이터는 쓸 수 없다.

> **금지선: 성공·실패 기준을 적기 전에는 질문 만들기로 넘어가지 않는다.**
> 나갔다 온 뒤에 기준을 정하면 사람은 반드시 자기에게 유리하게 해석한다.

---

## 1. 확인 가능한 문장으로

`내제품/왜.md` 칸 6의 가장 위험한 가정을 가져온다. 네 조각으로 나눈다.

| 조각 | 묻는 말 |
|---|---|
| **누가** | 어떤 조건에 맞는 사람입니까 |
| **어떤 조건에서** | 언제, 어떤 상황에서 |
| **어떤 행동을** | 눈으로 볼 수 있는 행동은 무엇입니까 |
| **얼마나** | 몇 명 중 몇 명이면 맞다고 하겠습니까 |

빈 조각이 있으면 그것만 다시 묻는다.

완성되면 판정한다.

> 이 문장에 적힌 일을 제가 옆에서 지켜본다고 칩시다. 맞았는지 틀렸는지 구분할 수 있습니까?

구분이 안 되면 아직 확인 가능한 문장이 아니다. "원한다", "필요하다", "생각한다"가 남아 있으면 대개 여기서 걸린다.

## 2. 가장 싼 방법 고르기

확인 방법 후보를 **세 개** 낸다. 반드시 **가장 싼 것부터** 놓는다.

싼 순서: 이미 있는 기록 읽기 → 사람에게 묻기 → 직접 해보게 하기 → 돈 받아보기

사용자가 "앱을 만들어서 확인하겠다"고 하면 되돌린다.

> 만들지 않고 확인할 방법이 남아 있습니까?

고른 뒤 **증거의 급수**를 알려준다.

> 말 < 클릭 < 시간 < 돈.
> "좋은 생각이네요"는 증거가 아닙니다. 이 방법으로 얻는 건 어느 급수입니까?

## 3. 기준을 먼저 적기

나가기 전에 두 줄을 받는다.

```
성공: (이렇게 되면 가정이 맞다)
실패: (이렇게 되면 가정이 틀렸다)
```

**실패 조건이 "아무도 안 쓴다" 같은 극단이면 다시 받는다.** 그런 기준으로는 절대 실패하지 않는다.
두 줄이 채워지기 전에는 다음 단계로 가지 않는다.

## 4. 질문 만들기

인터뷰 질문 **세 개**를 사용자가 쓴다. 내가 쓰지 않는다.
쓰고 나면 아래로 검사한다. 걸리면 그 질문만 다시 쓰게 한다.

| 걸러낼 질문 | 왜 |
|---|---|
| "이런 게 있으면 쓰시겠어요?" | 미래를 묻는다. 거의 전원이 "네"라고 답한다 |
| "○○가 불편하지 않으세요?" | 답을 심어 준다 |
| "어떤 기능이 있으면 좋을까요?" | 해결책을 묻는다. 그건 사용자의 일이 아니다 |
| "보통 어떻게 하세요?" | 일반론을 묻는다. 기억이 아니라 인상이 나온다 |

통과하는 질문은 **과거의 한 번**을 묻는다.

- "가장 최근에 그 일이 있었던 게 언제였습니까?"
- "그때 정확히 뭘 하셨습니까?"
- "그 방법을 쓰면서 제일 성가셨던 게 뭐였습니까?"

## 5. 나가기 전 점검

마지막으로 네 가지를 확인하고 내보낸다.

- [ ] 확인 가능한 문장이 있다
- [ ] 확인 방법이 정해졌다
- [ ] 성공·실패 기준 두 줄이 적혀 있다
- [ ] 질문 세 개가 검사를 통과했다

그리고 `내제품/근거.md`에 기록 틀이 준비돼 있는지 확인한다.

> 세 명에게 물어보고 오세요. **들은 말은 고치지 말고 그대로** 적으세요.
> 정리는 돌아와서 합니다. 지금 정리하면 기억이 아니라 해석이 남습니다.

조건에 안 맞는 사람에게 물었다면 그 기록에 `연습`이라고 표시하게 한다. 근거로 세지 않는다.

세션 끝에 `내제품/기록.md`에 한 줄 남기고 커밋을 권한다.
