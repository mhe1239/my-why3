## 1. 누구를 위한 것인가   [아직 가정]
**PS를 자습으로 기본 개념 문제까지는 무난히 풀지만, 배운 개념을 응용하는 문제에서는 접근 방식을 찾지 못해 막히는 사람**
- 재작성 2(26.10.02, 사용자 문장): 6번 칸 가정 8 판정으로 방향 전환(개념 → 문제의 어디에 쓰는지) + 강좌 조건 버림 + (다)로 좁힘. 좁힘 ○ / 맞는 사람 **본인(백트래킹)·A(stack) 2명** → 3명 기준 미달 / 돈 내는 사람: 학생 본인(가정)
- 판정(26.10.02): 좁힘 ○ / 실제 사람 3명 ○(본인·A·선배 — 선배는 막힌 이유 미정) / 돈 내는 사람 ○(가정) → **통과(아직 가정)**
- 이전 문장 2(26.09.29~10.02): "개념 위주의 강좌에서 교재 내용을 다 이해하고도, 문제의 낯선 표현 앞에서 앞에서 배운 이론과 매칭하지 못해 막히는 사람" — 버린 방향(문제 표현 → 개념). 또 가정 2 판정에서 "다 이해하고도"가 본인에게도 맞지 않음이 드러남
- 재작성(26.09.29, 사용자 문장): 좁힘 기준 통과. 떠올린 사람은 본인 1명 → 3명 기준 미달
- 쓰는 사람 / 돈 내는 사람(26.09.29): **둘 다 학생 본인** — 사용자 답 "학생 본인이지 않을까" → **가정**. 4주차에 확인
- 판정(26.09.29): 좁힘 ○ / 돈 내는 사람 ○(가정) / **실제 사람 3명 ✗** (본인 1명, 2자리 빈칸) → 미통과, 빈칸은 4주차에 찾을 사람
- 이전 문장: "학교 강의가 PPT,부실한 설명에 의존하나 과목의 원리까지 깊이 이해하는 것을 원하는 학생"
- 좁힘(26.09.29): 따로 공부하고 싶은데 **무엇으로 해야 할지 몰라 못 하는** 학생 — "이미 방법을 찾아 하는 학생"은 제외
- 수정(26.09.29): 위 "좁힘"을 버리고 2번 칸 쪽 사람(자료·개념은 알지만 문제에 넣는 법을 모름)을 대상으로 함. 이유(사용자): "1번은 자습에 가깝고, 2번은 이미 들은 강좌를 기준으로 어떻게 하면 더 심층 있게 할까라서 내 주제에 가깝다" — 1번 칸 문장은 아직 다시 쓰지 않음
- 결정(26.09.29): **강좌 조건 유지.** A는 수업 밖 자습이라 대상에서 제외 → 대상에 맞는 실제 사람 0명, 4주차에 "강좌를 듣고도 개념을 문제에 넣지 못한 사람"을 새로 찾아야 함
- 1번 칸 문장 재작성: **보류** (사용자가 3번 칸을 먼저 하기로 함, 26.09.29)
- 재작성 시작(26.09.29): 강좌 종류 선택지 (가) 문제 풀이형(자료구조·알고리즘) / (나) 개념 이해형(컴퓨터구조) / (다) 둘 다 중 **(나) 선택**
  - 경고: 2번 칸 문장은 A의 PS(문제 풀이형) 상황에서 나왔음 → (나)와 어긋날 수 있음. 3번 칸의 본인 막힘("눈에 안 보임")이 (나) 쪽

  - 구체적 상황(본인, **직접 겪음**, 컴퓨터구조 연습문제 12번): "하드디스크 설명으로 옳지 않은 것은? ④ 트랙 사이의 일정 공간은 저장 밀도를 높인다"
    - 책으로 개념 학습 후 **바로 풀지 못함** → 책과 문제를 번갈아 보며 풂
    - 답: ④ — 트랙 사이 공간은 인접 트랙 간섭(crosstalk) 방지용. 넓어지면 저장 공간이 줄어 밀도가 낮아짐
    - 주의: 이 문제는 개념을 **기억·확인하는** 문제에 가까움. 3번 칸 분류의 ②(응용과 묶지 못함)인지 ③(개념 이해 부족)인지 미정
    - 판정(26.09.29, 사용자 답): 책에는 "간섭 방지용 공간 → 넓어지면 저장 가능한 물리적 공간이 줄어듦"까지 있었음. "저장 밀도가 낮아짐"은 **직접 이어야 했음** → ②에 가까움 (개념은 알았지만 문제 표현과 잇지 못함)
    - 약한 점: 이어야 했던 간격이 **한 단계**(물리적 공간 감소 = 밀도 감소)로 작음. A의 경우(개념 → 코드 흐름)보다 간격이 좁음
- 떠올린 사람:
  1. 동아리원 A — 수업으로 C언어 기초는 함. "자습으로 어떻게 PS를 하면 좋을지 모르겠다"고 **직접 말함** (시점 미기록). stack·queue는 **수업 밖에서 혼자 공부**함 → "이미 들은 강좌 기준"과 어긋남
  2. 본인 — PS 방법을 찾기만 하고 실행 안 함 / 아예 안 함. "몰라서"인지 "알고도 안 해서"인지 **불분명**
     - 갱신(26.09.29): 컴퓨터구조 연습문제 12번(위) 경험으로 **새 1번 칸 문장에 맞음** — 현재 유일하게 맞는 사람
  3. 후보(26.09.29): C언어 수업의 누군가 — `int a,b` 입력 후 `a/b`를 출력했는데 **왜 소수점이 안 나오는지** 사용자에게 **직접 물어봄** (누구인지·시점 미기록)

     - 미정 ②: 정수 나눗셈을 **이미 배우고도** 잇지 못한 것인지(②), 아예 몰랐던 것인지(③)
       - 사용자 답(26.09.29): 그 친구는 수업 때 교수님 설명보다 **PPT를 읽었음**. PPT에 `float res=a/b` 예제가 있었음 → 내용은 **나간 뒤**였음
       - 주의: PPT를 **읽었다 ≠ 이해했다**. 1번 칸 문장의 "교재 내용을 다 이해하고도"에 맞는지는 아직 모름
       - 판정(26.09.29, 사용자 답): 설명을 듣고 **처음 듣는 것처럼** 반응함 → ③(개념 이해 부족). **1번 칸 대상에서 제외**

  - (26.10.02 재작성 2 기준) 본인 — 백트래킹: 개념 손 추적·개념 문제 풂 → "아름다운 수"에서 접근 방식 못 찾음 (6번 칸 참고) — **맞음**
  - (26.10.02 재작성 2 기준) A — stack: 개념 공부 후 문제의 어디에 stack을 쓸지 몰라 막힘 (멘토링 채팅) — **맞음**
  - (26.10.02 후보) 선배 — **9월 7일 직접 대화**: "내 약점이 이중 for라는 걸 느꼈다", 변수 추적도 쉽지 않아서 **GPT 코드를 보고 차근차근 쓰는 중**

## 2. 그 사람의 어떤 문제인가   [아직 가정]
**개념은 알지만, 문제에서 배운 개념을 어떤 조건에서 써야 할지 명세하는 방법을 모르기 때문**
- 판정(26.10.02, 문장 시도 6): 해결책 아님 ○ / 증상이 아니라 이유("명세하는 방법을 모름") ○ / 구체적 상황 ○(본인 "아름다운 수": 시작·되돌아갈 조건 / A 후위표기법: 우선순위 처리 조건) → **통과(아직 가정)**
  - "써야 할지"의 뜻(사용자 확인): 개념을 쓸지 말지가 아니라, **쓰는 건 알지만 언제 시작·멈춤·되돌아가기 등을 할지** (2번 뜻)
  - 약한 점: 문장만 읽으면 "써야 할지"가 "쓸지 말지"로 읽힐 수 있음. 선배(PCCE 심폐소생술, "변수 추적")에게도 맞는지 모름 → 4주차
- 이전 문장(26.09.29~10.02): "개념을 문제 흐름 안에 어떻게 넣을지 몰랐기 때문에 구현에서 막힌다" — "구현에서"가 본인(쓰기 전에 막힘)에게 맞지 않음
- 통과(26.09.29): 해결책 아님 / 결과가 아니라 막힌 이유 / 동아리원 A의 상황이 붙어 있음
- 다시 보기(26.10.02, 1번 칸 재작성 2에 맞춰):
  - 약한 점: "**구현에서**" — A 한 사람 사례로 만든 문장. 사례 3개(본인·A·선배)의 막힌 지점이 같은지 모름
  - 본인(아름다운 수, 사용자 답): **코드를 쓰기 전에** 막힘. 이유: **시작 상태를 정의하지 못함** → "구현에서"와 맞지 않음
  - A(사용자 답, 26.10.02): 기본 개념 후 백준 10828(스택)은 풂 → **후위표기법** 문제에서 괄호 처리는 만들었고, **연산자 우선순위를 어떻게 할지**에서 막힘 → **코드를 쓰는 중에** 막힘
  - 비교: 본인은 쓰기 **전**, A는 쓰는 **중** → "구현에서"도 "쓰기 전"도 공통이 아님
  - 공통점(사용자 답, 26.10.02): "조건을 모른다? 문제에서 이 개념을 어디서 써야 하는지 모호할 수 있고, 어디서 쓸지는 알아도 어떻게 코드화하는지 모른다. **결국에는 어떤 조건에서 연산자 우선순위를 먼저 구성할지, 어떤 조건에서 탐색을 멈추고 돌아갈지·시작할지를 모른다**"
    - 앞의 두 갈래("어디서 쓸지 모호" / "어떻게 코드화할지 모름")는 서로 다른 말. 마지막 줄("**어떤 조건에서** ~할지 모른다")이 본인·A에 공통
  - 문장 시도 3(26.10.02): "어떤 조건에서 이 개념을 써야 할지 모르기 때문에 코드화하는 단계에서 막힌다" — 미통과
    - 약한 점: "이 개념을 **써야 할지**"는 개념을 쓸지 말지를 모른다는 뜻으로 읽힘. 본인·A는 **어느 개념을 쓸지는 알았음**(백트래킹·stack). 모른 것은 개념 안의 동작(시작·멈춤·되돌아가기 / 우선순위대로 꺼내기)을 **언제 하는지**
  - 문장 시도 4(26.10.02): "이 개념을 어떤 조건에서 **응용해야 할지** 모르기 때문에…" — 미통과. "응용"은 막힌 결과를 가리키는 말이라 시도 1("응용하지 못했기 때문에")과 같은 순환
  - 문장 시도 5(26.10.02): "이 문제에서 배운 개념을 어떤 조건에서 써야 할지 모르기 때문" — 시도 3과 같은 모호함("써야 할지" = 개념을 쓸지 말지?). 선택지 (가) 동작의 조건 / (나) 옮기기 중 고르지 않음 → 뜻 확인 중
  - 정정 반영: A는 stack을 "알아본" 것이 아니라 문제에 stack이 적혀 있었음(6번 칸 가정 8) — 아래 "막힌 지점(A의 말)" 줄은 이 정정 전 기록
- 이전 초안(증상이라 미통과): "수업 기반으로 공부를 해도 과목에 대한 제대로된 이해가 부족함 / 이에 따라 관련 프로젝트/면접 질문에 대답하기가 어려워짐 / 이 과목과 다른 과목들이 제대로 연결이 되지 않아 새로운 결과가 나오기 쉽지 않음"
- 구체적 상황(동아리원 A, 들은 말): 배열 다음 stack·queue 개념을 공부한 뒤, **개념을 실제 문제 풀이에 쓰는 데서 어려움을 느끼고 그때 포기함**
  - 막힌 지점(A의 말): 문제 키워드가 stack에 해당한다는 건 **알아봄** → **코드로 옮기지 못함** → AI에게 물어봤지만 **"스스로 풀지 못했다"**고 느낌 → 포기
  - 문장 시도 2(채택): "개념을 문제 흐름 안에 어떻게 넣을지 몰랐기 때문에 구현에서 막힌다"
  - 문장 시도 1: "개념을 통해 응용하지 못했기 때문에 문제를 푸는 것에서 막힌다" — 미통과(원인과 결과가 같은 말: 응용 못함 = 문제 못 풂)
  - 코드로 못 옮긴 이유(사용자 선택): stack **구현은 할 줄 아는데, 문제의 흐름 안에 어떻게 끼워 넣을지 몰랐다** — 제시된 선택지 중 고름. **사용자 해석**(예전에 A와 주고받은 문자를 근거로 판단). 문자 원문은 4주차에 `근거.md`로 옮겨 확인
